Development

Build and test

Build the webhook image from source:

make build-image IMAGE=ghcr.io/dotinfra/cert-manager-webhook-nameshield TAG=0.1.0
make push-image  IMAGE=ghcr.io/dotinfra/cert-manager-webhook-nameshield TAG=0.1.0

Unit tests (no external dependency):

make unit-test

The cert-manager DNS01 conformance suite requires a real Nameshield zone and API token, plus the envtest binaries (downloaded automatically):

export NAMESHIELD_ZONE=example.com       # a zone hosted by Nameshield
export NAMESHIELD_TOKEN=<api-token>       # token with DNS rights on that zone
make test

All DNS webhooks deployed publicly are expected to run and pass this suite.

Render the chart locally:

make rendered-manifest IMAGE=ghcr.io/dotinfra/cert-manager-webhook-nameshield TAG=0.1.0

Documentation

This site is built with MkDocs from the docs/ folder (mkdocs.yml at the repository root). To preview it locally:

pip install mkdocs==1.6.1
mkdocs serve

The docs.yaml workflow builds the site on every push/PR touching docs/, mkdocs.yml or the workflow, and publishes it on main to the root of the gh-pages branch, so the documentation is the GitHub Pages home page. The Helm chart repository (index.yaml) is preserved at the same root.

CI and releases

Three GitHub Actions workflows are defined in .github/workflows/:

  • ci.yaml — runs on every push and pull request on main: gofmt check, go vet ./..., unit tests (go test ./nameshield/...), helm lint and helm template on deploy/cert-manager-webhook-nameshield, and a Docker image build (load only, no push).
  • docs.yaml — builds the MkDocs site and publishes it to the root of gh-pages, as the Pages home page (see above).
  • release.yaml — runs on push of a v* tag only (one tag = one release, no extra chart tags/releases): validates the semver tag, builds and pushes the multi-arch image to GHCR (<version>, <major>.<minor>, <major>, latest on stable releases, sha-<short-sha>), sets the chart version/appVersion to the tag version, packages it with helm package, creates the single GitHub release on the tag with the .tgz attached, and publishes the .tgz + regenerated index.yaml to the gh-pages branch (chart repository at the root of the Pages site, next to the documentation).

All workflows rely on the default GITHUB_TOKEN only — no extra secrets are required.

Cutting a release

git tag vX.Y.Z
git push origin vX.Y.Z

Everything is aligned on the same release version: the Docker tag X.Y.Z, the chart version/appVersion X.Y.Z, and the chart's default image.tag (which equals appVersion, i.e. X.Y.Z).

GitHub Pages setup

In Settings → Pages, set Build and deployment to Deploy from a branch and select the gh-pages branch with the / (root) folder. The site then serves, from the same branch:

  • the documentation at the root, https://dotinfra.github.io/cert-manager-webhook-nameshield/ (home page);
  • the Helm chart repository at https://dotinfra.github.io/cert-manager-webhook-nameshield/index.yaml (.tgz archives at the root).

The gh-pages branch itself is created automatically (as an empty orphan branch) by the release workflow on the first chart publication.
